Install and first run

One command to install, a short setup the first time you run it.

motita is one static binary. There is nothing to compile and nothing else to install first.

Install

# Linux and macOS
curl -fsSL https://motita.kodingvibes.com/install.sh | sh

# Windows (PowerShell)
irm https://motita.kodingvibes.com/install.ps1 | iex

The installer detects your system and architecture, downloads the matching binary, and checks it against the release's SHA256SUMS. If the check does not match it stops and leaves your system untouched. It installs without administrator rights, then runs the binary once to prove it starts.

First run

Type motita. With no configuration, a short setup starts on its own. It has five steps and writes nothing until you have seen the result:

  1. Provider. Which model service answers: OpenAI, ChatGPT (Codex), GitHub Copilot, Ollama, Anthropic, your Claude subscription, Gemini or Qwen.
  2. Connect. Log in with your account, or paste an API key (hidden as you paste it).
  3. Model. Pick one of the suggested models, or type any model ID.
  4. Check. What decides that a task is really done. The default is to detect it from the project: your make test, go test, npm test, cargo test. A project with an unusual build lists its own commands in .motita/anchor.
  5. Review and save. Every answer on one screen. n goes through them again.

Run the setup again at any time with /config inside motita or motita config. It offers to keep your current key and login, and keeps the previous file as motita.yaml.bak.

When something does not work

motita doctor checks the machine before anything runs, one line per check: the build against the system, the shell, DNS, your PATH, git, the configuration and the sandbox it would build. It needs no key and calls no model.

Older and smaller machines are a target, not an afterthought: there are builds for 32-bit x86, ARM, ARM64, macOS and Windows.
