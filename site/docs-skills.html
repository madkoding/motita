Skills: what it learns

A shelf of procedures it reads, writes and keeps tidy, no retraining.

motita keeps a library of procedures: documents describing how a kind of work is done, with the steps, the commands that work and the pitfalls someone already paid for. The model looks one up when it needs it and writes a new one when it learns something. They are plain files, so you can read, fix and version them.

How it improves

  • A fresh install starts with built-in procedures (running commands, files, git, HTTP APIs, web search, toolchains, verifying a change, diagrams and reports).
  • /good and /bad land on the procedures that were actually used, and the library is searched by what has worked before.
  • No fine-tuning, no extra API, no extra bill. A ledger next to a shelf.

See and control the shelf

The browser has a Skill library window: every document, what it is for, how often it was used, the document itself rendered, and a switch to turn one off without losing it.

A project can keep its own procedures in <project>/.motita/skills/; they are searched first and shadow the shared library.

The curator

Left alone, a shelf rots, so a curator runs weekly, only when nobody has talked to motita for two hours. It uses no model for the work that matters and touches only documents the agent wrote:

  • Unused for 14 days: marked stale, still searchable.
  • Stale for 30 more days: archived, never deleted, one command brings it back.
  • Pinned documents are exempt from every automatic step. Nothing automatic ever deletes.
motita curator status
motita curator run --dry-run
motita curator pin build-firmware
