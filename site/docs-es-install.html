Instalación y primer uso

Un comando para instalar y una configuración corta la primera vez.

motita es un único binario estático. No hay nada que compilar ni nada más que instalar antes.

Instalar

# Linux y macOS
curl -fsSL https://motita.kodingvibes.com/install.sh | sh

# Windows (PowerShell)
irm https://motita.kodingvibes.com/install.ps1 | iex

El instalador detecta tu sistema y arquitectura, descarga el binario que corresponde y lo verifica contra el SHA256SUMS de la versión. Si no coincide, se detiene y tu sistema queda intacto. Se instala sin permisos de administrador y ejecuta el binario una vez para comprobar que arranca.

Primer uso

Escribe motita. Si no hay configuración, arranca solo una configuración corta de cinco pasos. No escribe nada hasta que ves el resultado:

  1. Proveedor. Qué servicio de modelos responde: OpenAI, ChatGPT (Codex), GitHub Copilot, Ollama, Anthropic, tu suscripción de Claude, Gemini o Qwen.
  2. Conexión. Inicia sesión con tu cuenta o pega una API key (queda oculta al pegarla).
  3. Modelo. Elige uno de los sugeridos o escribe cualquier ID de modelo.
  4. Verificación. Qué decide que una tarea está realmente terminada. Por defecto se detecta desde el proyecto: tu make test, go test, npm test, cargo test. Un proyecto con una compilación poco habitual lista sus propios comandos en .motita/anchor.
  5. Revisar y guardar. Todas las respuestas en una pantalla. n las recorre otra vez.

Puedes repetir la configuración cuando quieras con /config dentro de motita o con motita config. Ofrece conservar tu clave y sesión actuales, y guarda el archivo anterior como motita.yaml.bak.

Cuando algo no funciona

motita doctor revisa la máquina antes de ejecutar nada, una línea por prueba: la compilación frente al sistema, el shell, el DNS, tu PATH, git, la configuración y el sandbox que construiría. No necesita clave ni llama a ningún modelo.

Las máquinas antiguas y pequeñas son un objetivo, no un detalle: hay compilaciones para x86 de 32 bits, ARM, ARM64, macOS y Windows.
